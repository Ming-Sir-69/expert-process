# 全量工作流：组织复杂任务

与[共同核心](core.md)配合使用。适合长期、多阶段、依赖复杂或需要协作交接的任务。全量提供组织能力，不规定行业阶段数，也不要求读完所有参考或为每个角色建卡。

## 模块接口

| 要素 | 约定 |
|---|---|
| 目标 | 组织必要阶段，保持责任、状态与交接一致 |
| 输入 | 当前请求、已有项目材料、任务状态和已授予的授权 |
| 职责 | Agent承担专业组织与取舍；用户提供其专属信息与必要授权 |
| 处理 | 根据依赖和知识缺口组合模块，变化时只重审受影响部分 |
| 输出 | 实际交付、必要的阶段交接，以及服务续接的活文档 |
| 验收 | 输出覆盖目标；依据、待答和未验证项明确；不以文件数量代替完成 |
| 交接 | 下一节点取得所需输出、适用条件、当前状态与未决事项 |

## 用多少，取决于问题

先考虑现有项目材料是否已足够。需要独立记录时，在完整工具包根目录执行：

```bash
python3 cli/eca.py new example --mode full --title "多阶段任务"
python3 cli/eca.py status example
```

档案位于外部数据目录的`runs/`，包含四份活文档：

| 文件 | 承担什么 |
|---|---|
| `1_简报.md` | 目标、约束、完成条件、适用偏好与已有授权 |
| `2_作战图.md` | 实际阶段、责任、交接及需要追溯的重要选择 |
| `3_日志.md` | 必要执行记录、关卡事件、影响后续的偏离 |
| `4_验收复盘.md` | 实际检查、完成边界、遗留与有价值的复盘 |

它们是当前状态入口，不要求抄录全部对话、每次命令或全部思考。产出按任务需要放`outputs/`；需保留的过程稿和生成脚本放`outputs/drafts/`，均不写回工具源码目录。

以下是组织活动的导航，不是必须依次走完的五个阶段：

| 活动 | 何时需要 | 采用的方法 | 记录位置 |
|---|---|---|---|
| 明确简报 | 目标或约束尚未稳定 | 确定完成条件和必要本人信息；已有答案不重复问 | 简报 |
| 补齐知识 | 存在影响结果的知识缺口 | 查对应行业依据；仅值得复用时整理卡片 | 来源、现有材料或可选`cards/` |
| 组织方案 | 存在依赖、协作或重要分歧 | 列实际阶段、责任、输入输出和取舍 | 作战图 |
| 产出与调整 | 方案可推进 | 执行、检查；有新信息时更新受影响部分 | 产出、必要日志和关卡 |
| 完成与沉淀 | 达到交付节点 | 对照完成条件，保留未知；有收益再复盘或提炼 | 验收复盘 |

可先做低成本探查再规划，可在执行中补调研；前提变化时也可重定义问题。不要为凑导航阶段补造流程。局部高风险动作只加强相关约束，不默认增加无关的调研、档案或审批。

## 阶段与模块的共同边界

作战图只维护一张实际任务的阶段表。对确需组织的节点使用目标、输入、职责、处理、输出、验收、交接七项：

- 输出应覆盖下一节点所需输入，并带上适用版本、条件和必要来源。
- 职责写清谁承担专业判断、谁提供专属信息、谁接收结果；一个Agent可兼任多个视角，不强制拆成多个Agent。
- 状态用未开始／进行中／待用户／已完成／已裁剪／需重做。未做不能伪装完成；已列但撤销的节点说明原因，未采用的模块不必逐项列裁剪说明。
- 专家考虑点、检查项、自由度和关卡写入相应单元格，不另填重叠表。
- 上游变化只重审依赖它的下游，保留仍有效的产出。先用[整合方法](integrate.md)处理依赖与专业分歧，确需本人信息时再用[关卡](gates.md)。

重要决定需要追溯时才登记算／查／问／确认及依赖。它们分别描述信息处理和决定权，不要求每件事依次过四道工序；“行业没有共识”也不自动等于“问用户”。

## 续接与工具边界

中断后先`status`，再读当前简报、作战图和未决事项。用户答复后更新实际受影响的约束，不重写事前关卡内容。旧的四文件和v0.2档案继续兼容；CLI不自动把轻量档案转换为全量，需要时新建全量档案并引用原任务。

CLI记录和检查结构，不执行模型推理，也不控制宿主Question面板的计时。默认不添加自动答复时限；用户可约定等待提醒。宿主超时、关闭或清除问题仍是未答，不能当成推荐项已被选中。

`eca check`按档案模式检查结构、关卡关联、待答与回写提醒；`--strict`把提醒视为未通过。它不证明行业判断正确、用户已认可或待决动作已经获得授权。

不再有续接、协作或追溯需要时，可以回到[轻量用法](lite.md)，不为保留全量形式继续产生记录。

## 采用来源

- LangGraph节点接收状态、输出更新并交给后继；中断保存状态后由外部输入恢复：https://docs.langchain.com/oss/python/langgraph/interrupts
- Claude Code输入回调可持续挂起：https://code.claude.com/docs/en/agent-sdk/user-input
- Codex用户输入请求有可空的autoResolutionMs；客户端可配置超时，不能据此假定所有宿主默认秒数相同：https://learn.chatgpt.com/docs/app-server

本工具采用这些状态与交接原则，继续使用Markdown档案和Python标准库，不引入其运行时依赖。
