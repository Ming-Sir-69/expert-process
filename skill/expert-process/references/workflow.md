# 模块接口与阶段交接

## 模块接口

| 要素 | 约定 |
|---|---|
| 目标 | 统一模块与阶段的边界 |
| 输入 | 简报、任务状态和已授予的授权 |
| 职责 | Agent维护接口；用户提供其专属信息 |
| 处理 | 按同一接口描述节点，再按任务裁剪 |
| 输出 | 四份活文档、卡片、阶段交接和决策记录 |
| 验收 | 字段与引用可查；未验证和待答状态明确 |
| 交接 | 下一节点取得当前输出、状态与未决事项 |

统一的是输入输出、责任与验收结构；任务内容、行业阶段数和调研深度按实际需要裁剪。

## 五个工作阶段

| 阶段 | 输入 | 处理 | 输出 | 下一步 |
|---|---|---|---|---|
| 简报 | 当前请求、约束、适用偏好来源 | 明确目标、完成标准与交互方式 | 1_简报.md | 调研 |
| 调研 | 简报与已有卡片 | 补齐当前知识缺口，先算/查 | cards/与来源 | 作战图 |
| 作战图 | 简报、卡片、未决事项 | 实际阶段、专家职责、决策分流与交接 | 2_作战图.md | 执行与关卡 |
| 执行与关卡 | 已定方案与当前输入 | 产出、验证；需要本人信息时暂停 | 3_日志.md、outputs/ | 验收或返回受影响节点 |
| 验收与复盘 | 交付、约束和证据 | 逐项验收、按范围沉淀 | 4_验收复盘.md、卡片/来源引用 | 交付与后续复用 |

作战图只维护一张实际任务的阶段表，用同一七字段接口：目标、输入、职责、处理、输出、验收、交接。状态用未开始/进行中/待用户/已完成/已裁剪/需重做。裁剪写明原因，不能把不用的步骤伪装成已完成。五个工作阶段是导航；实际表按任务列必要阶段，不重复抄一份导航。专家、检查项、自由度和关卡可写入相应职责/处理/验收/交接单元格，不另填一张重叠表。

交接时核对：输出是否覆盖下一模块所需输入；使用哪些版本/卡片/用户答复；尚有哪些未知或等待；未通过时返回哪个节点。上游变化只重审依赖它的下游，保留未受影响的结果。

## 工具边界

CLI记录和检查本地结构，不执行模型推理，也不控制宿主Question面板的计时。默认不添加自动答复时限；用户可以约定等待提醒时间。即使宿主超时、关闭或清除提问，也只记为未答并保留待决状态，不能当成推荐项被选中。

`eca check`检查接口字段、阶段完成字段、关卡/决策关联、待答和回写提醒。`--strict`把提醒也视为未通过。它不证明行业判断正确、用户已认可或待决动作已经获得授权。

- LangGraph节点接收状态、输出更新并交给后继；中断保存状态后由外部输入恢复：https://docs.langchain.com/oss/python/langgraph/interrupts
- Claude Code输入回调可持续挂起：https://code.claude.com/docs/en/agent-sdk/user-input
- Codex用户输入请求有可空的autoResolutionMs；客户端可配置超时，不能据此假定所有宿主默认秒数相同：https://learn.chatgpt.com/docs/app-server

本工具采用这些状态与交接原则，继续使用现有Markdown档案和Python标准库，不引入其运行时依赖。
