# 复盘与沉淀：保留真正值得复用的内容

## 模块接口

| 要素 | 约定 |
|---|---|
| 目标 | 沉淀本次有效知识与有边界的流程经验 |
| 输入 | 验收、关卡事前/回顾分类、用户反馈和资料变化 |
| 职责 | Agent归纳；本人反馈不由模型代写 |
| 处理 | 比较实际结果，分开方向变化和质量收益，按范围回写 |
| 输出 | 有价值的项目记录、卡片或复用候选，保留适用条件 |
| 验收 | 不把一次试点或事后推测当因果证明；来源和未知保留 |
| 交接 | 后续任务按适用范围复用；稳定重复需求才交给forge |

目录：复盘 → 卡片入库 → 偏好回写 → 复用前判断时效 → 刷新与扩充

## 1. 何时复盘

当前任务出现值得保留的经验、偏离或反馈时再复盘，不要求小任务逐次填写固定问卷。全量档案在`4_验收复盘.md`中保留有用结论；轻量任务可在现有记录里简述，也可以不另存。

按需要选择以下角度：

1. **结果**：完成标准逐条达到了吗？用户怎么评价？（用户还没看就写"待用户反馈"）
2. **问**：哪些提问改变了方向，哪些可以不问？使用CLI记录时可用`eca stats`区分事前、回顾与未知；方向变化不证明质量收益
3. **算、查**：哪些本该在关卡之前做、却做晚了？哪些检查应该做成 `tools/` 里的脚本？
4. **流程与专家**：调研到的流程哪里贴合、多余、漏了？哪些考虑点真正挡住了问题，哪些是空话？
5. **工具包**：哪一步最费时间、哪一步最有价值？要改什么？
6. **沉淀**：哪些内容值得留在任务/项目，哪些已有充分理由额外提炼？没有收益就不增加全局记录。

用户要求“做完再看”且已有足够授权时自主推进；不因此忽略新证据或继续已知错误方向。重要调整在现有任务记录保留依据，确有无法替代的本人信息或未获授权动作时只暂停相关部分。

## 2. 卡片入库

- 仅在值得复用时整理卡片，放外部档案的`cards/`，执行`eca save <run>`：按type进入数据目录下的`library/processes/`、`library/experts/`、`library/preferences/`，并重建`library/INDEX.md`。不为每次任务创建卡片或入库回执。
- 库里已有同 id 的卡：旧版自动移到 `library/_history/`；新版要合并旧版仍然有效的内容，不要整体覆盖丢信息。

## 3. 偏好回写

- 关卡得到的新信息保留日期、原话来源和适用条件。通常先更新任务/项目记录；是否另建卡片或提炼为跨项目候选，按cards.md的判断线索由Agent决定。
- 被推翻的旧偏好移到"已推翻"表，写明推翻日期和改成了什么——防止下次又照旧记录做
- 只写用户说过的；模型的推测不写进偏好卡
- 当前作品的定稿参数留档案；不把它升级为通用偏好。

## 4. 复用前判断时效

用 `eca find` 找到旧卡后先看 `updated` 和 `confidence`：

- 行业卡：结合领域变化速度、版本和当前风险判断时效。平台规范、软件工具与法规等易变信息核对当前适用来源；稳定原则也要看本任务的适用条件，不设统一月数作为有效期。
- 偏好卡：结合原话、范围、当前请求和冲突判断，不将一次选择扩为长期偏好。只有过期或冲突会实质影响本次结果且缺少本人答案时才问；日期提醒本身不要求开关卡。
- confidence 为低的卡：当作线索，不当作结论。

## 5. 刷新与扩充

- **刷新**：来源更新了、规范改版了、或复盘发现卡片说错了 → 改卡片、更新 `updated`，写一句改了什么。
- **扩充**：卡片方向对但不够深（新出现的角色、阶段或考虑点）→ 增补，不推倒重写。
- 同一张卡被多个任务用过并验证有效后，可把 confidence 调高。
