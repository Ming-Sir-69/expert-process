# 关卡：准备、等待与答复

## 模块接口

| 要素 | 约定 |
|---|---|
| 目标 | 取得任务所需的本人答案或未覆盖的授权 |
| 输入 | 真正缺少的本人信息或授权、可比较选项和已有约定 |
| 职责 | Agent准备和记录；用户回答或授权 |
| 处理 | 保存待决状态，提问并等待；答复到达后追加结果 |
| 输出 | 真实答案与更新后的约束；使用CLI时保留事前和答复事件 |
| 验收 | 无答不算已答；事前与回顾分开；确认不能由超时替代 |
| 交接 | 当前任务与相关事实源；下游按新约束继续 |

## 1. 进入条件

仅在缺少必要的本人专属信息，或动作尚未获授权时提问。专业取舍由Agent完成，行业没有共识不自动成为提问理由。已有答案与明确授权不重复询问；当前用户指令优先。

提问本身不要求建档。当前对话足以保留状态时直接问；以下CLI登记用于确需续接或追溯的任务。轻量档案的关卡写入`任务.md`，全量档案写入`3_日志.md`，均位于外部数据目录。

## 2. 提问前登记

先做与本选择相关的计算和查证，筛掉不可用选项，准备足以比较的选项、建议和风险；简单事实缺口可以直接问，不强行设计选择题。选项数适配宿主面板，不凑数；视觉任务可按呈现需要给实际尺寸、亮暗场景或参考作品板。对重要编号与指代复述具体特征。

提问之前保存给了什么、默认会选什么、关联决定。示例：

```bash
python3 cli/eca.py gate <run> --id G1 --title 方向选择 --decision D1 --gave "已筛过的A/B方案" --counterfactual "默认选A，因为…"
```

该事件记为事前登记、待答。用户实际答复到达后追加：

```bash
python3 cli/eca.py gate <run> --id G1 --resolve --answer "用户选B及其原话" --changed 是 --writeback "简报约束、决策D1、相应偏好来源"
```

答复只追加，不能通过此命令改写先前给出的选项或默认方案。一次调用同时给出方案和答案的旧写法仍可用，但按回顾记录统计；没有可追溯登记方式的旧数据归未知，明确事后补记的归回顾。

## 3. 等待约定

默认无额外超时，持续保留待答。用户可在简报约定等待方式，或用`--wait-seconds N`记录某关的提醒秒数；这不是宿主计时器，也不会自动代用户选择。取消、宿主超时和提问被清除均属于未答，可恢复或重新提问。

用户明确授权自主推进时，可以按授权范围、已知约束和明示假设继续；确有帮助时用变体覆盖偏好不确定性，不强制增加版本。全量档案将授权来源写进简报并标记`自主推进：已授权`，轻量档案在`任务.md`保留来源。已有授权足够时无需开头再问；真正缺少且无法替代的本人信息仍等待。未经授权的“确认”动作不能因计时或假设被放行。

## 4. 答复与回写

五个结果字段保留：给了、答、没问会怎样、改变方向、回写。另存状态、登记方式、关联决定、等待秒数和登记时间。改变方向写是/否/未知；没有用户答案不能填写方向结论。

答复后更新实际受影响的任务约束；有全量决策登记时更新为`已答 G1`，没有就不补造表格。新信息回写到它实际适用的任务/项目记录；是否额外提炼为复用内容，由Agent按cards.md判断，不自动扩展到全局。不要把单个作品的定稿参数升格成个人通用偏好。

## 5. 统计边界

`eca stats`按事前/回顾/未知分组，待答不计作已改变方向；同一个G编号的准备和答复算一关。方向变化是复盘标注，不等同于质量提高或因果收益。历史回顾记录不作为事前登记的验证结果。

## 6. 跟随的机制

采用先保存待决方案、暂停、收到外部输入后恢复的模式，依据Claude Code用户输入回调与LangGraph中断机制；官方入口见workflow.md。工作区保存问题状态，避免宿主会话结束后被误认为用户已回答。


## 授权代选与常见失误

用户明确说“你帮我选”时，在已授权范围内给出选择和理由，记录为授权代选，不循环把同一选择再问回去。方案数以可比较、可区分为准，遵守宿主面板限制；3–5项可作为合适场景的参考，不作为所有任务必须凑齐的数量。

注意避免：把未筛选的选项交给用户；先问依赖上游的细节再问方向；答复后不更新约束；把模型猜测写成用户偏好；选项过多却缺少真正区别。这些原则同时适用于文档、规划、分析和开发任务，视觉呈现只是可选的领域做法。
