# 轻量用法：直接解决当前问题

与[共同核心](core.md)配合使用。这是默认入口，适合局部修复、一次性分析、方案取舍和明确的小交付；无需先选行业流程、拆专家、填表或建立档案。

## 选当前缺少的能力

先明确要解决什么、受什么约束、做到什么算完成。已有明确上下文就直接使用。Agent按实际缺口补方法：不了解规格才查规格，有重要分歧才比较方案，需要本人信息才问；不把所有参考模块都读一遍。

可计算约束、行业依据、本人信息与动作授权是可组合的判断角度，不是每个问题必须依次经过的四道工序。用户说“你帮我选”时在已授权范围内选择并说明重要理由，不把同一个选择再问回去。

局部高风险动作单独检查权限、影响和恢复条件。比如一处涉及生产数据的修复需要相应约束，不因此要求完整行业调研或四份活文档。

## 记录可以省略

能在当前对话或现有项目材料里处理清楚，就不新建记录。交付说清结果、必要依据、实际检查和未决事项，篇幅随问题而定，不要求固定回复模板或复盘。

需要中断续接、保留关键选择时，可在完整工具包根目录执行：

```bash
python3 cli/eca.py new example --mode lite --title "局部问题"
python3 cli/eca.py status
```

轻量档案只建`任务.md`和模式元数据`.eca.json`，位于外部数据目录的`runs/`。按需要维护目标、当前处理与决定、结果和未决事项；无需专家卡、阶段表或关卡数量。只有实际需要持久问题状态时才用`gate`，关卡写入同一`任务.md`。

```bash
python3 cli/eca.py gate <run> --id G1 --title 目标范围 --gave "本次包含A或A+B" --counterfactual "按当前证据默认只处理A"
python3 cli/eca.py gate <run> --id G1 --resolve --answer "用户选择A+B" --changed 是 --writeback "任务.md的范围"
```

此时才读[关卡规则](gates.md)。未建档时仍应保留真实待答状态，不为了统计单独补造档案。

## 何时增加组织结构

当问题出现互相依赖的阶段、多方协作、持续变化的约束，或上下文已难以可靠续接时，取用[全量工作流](workflow.md)中的相应组织方式。全量提供可组合的方法，不要求一次补齐所有卡片和阶段；方法切换也不代表可以重写先前事实或把未答记成已答。

CLI不自动把轻量档案改成全量档案。确需四份活文档时可用新的slug建立`--mode full`档案，在简报引用原轻量档案，保留先前依据和未决状态。

例如，定位接口故障可直接查现场、提出假设并检查修复；只有进一步发现多个系统的迁移依赖和交接需要时，才组织阶段与责任。无需先把简单问题包装成新项目。
