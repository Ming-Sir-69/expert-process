# 整合：作战图与决策登记

## 模块接口

| 要素 | 约定 |
|---|---|
| 目标 | 形成可执行、可交接的任务方案 |
| 输入 | 当前目标、已有材料、适用卡片或依据及未决事项 |
| 职责 | Agent组织行业适配；本人决定专属取舍 |
| 处理 | 按实际需要组织阶段、依赖和重要取舍 |
| 输出 | 可执行方案；需要交接时使用单张阶段表及必要决策记录 |
| 验收 | 输入输出衔接，检查项可判断，待答事项未伪装已定 |
| 交接 | 执行使用已定方案；答复或上游变化时更新受影响项 |

目录：作战图 → 决策登记 → 每步自由度 → 冲突处理 → 偏好与专家意见冲突 → 输出

简单问题可直接形成方案，不填作战图。以下表格用于确需多阶段组织的全量任务；已有项目计划可直接复用。

## 1. 作战图（全量档案写进 2_作战图.md）

只维护一张实际任务的阶段表，把必要的专家分工与检查合在同一处：

| 阶段 | 目标 | 输入 | 职责 | 处理 | 输出 | 验收 | 交接 | 状态 |
|---|---|---|---|---|---|---|---|---|

- 职责写主导与把关；处理写必要的方法和自由度；验收写检查项与证据；交接写接收方、必要关卡G编号及未决事项。
- 一个人（或一个模型）可以兼任多个角色；写清此刻戴的是哪顶帽子。
- 检查项从专家卡的"考虑点"里挑与本阶段相关的，不全量照搬。
- 适用于当前任务的用户要求和否决是约束，写在简报或已有项目记录，作战图引用即可；过期或超出范围的偏好不直接套用。
- 只列本任务需要的阶段；已经列出又撤销的阶段说明原因，不为每个未采用模块补裁剪说明。

## 2. 决策登记

只登记会影响后续依赖、需要本人答复或值得追溯的重要决定，不记全部日常判断。类型（算／查／问／确认）按主导处理方式填写；同一决定的其他查证写进依据，不要求依次过四道工序：

| # | 决定 | 类型 | 次序 | 依据 / 由谁定 | 状态 |
|---|---|---|---|---|---|
| D1 | 报告的主要读者 | 问 | 1 | 关卡G1（示例） | 已答 G1 |
| D2 | 图表的表达方式 | 问 | 3 | 先核对字段D3，再由G2选择（示例） | 已答 G2 |
| D3 | 输入字段是否完整 | 算 | 2 | 字段检查脚本（示例） | 已定 |

- **次序**：上游先于依赖它的下游；"问"之前把它依赖的"算""查"排在前面。
- 执行中出现需要追溯的新决定，更新相应记录。
- `eca check`核对问/确认是否关联真实已答关卡；问类使用假设时必须有简报中的明确自主授权，确认不能靠假设放行。

能核对的硬约束用“算”，缺行业依据用“查”；专业流派没有共识时，由Agent辨明条件并选择。只有缺少本人专属信息才“问”，动作尚未获授权才“确认”。已有明确答案或授权不重新询问。

## 3. 每步自由度

| 自由度 | 适合 | 写法 |
|---|---|---|
| 高 | 多种做法都合理、靠判断 | 写目标和原则，让模型自己选路 |
| 中 | 有偏好的做法但允许变化 | 写步骤和参数范围 |
| 低 | 容易出错、要求一致、不可逆、可精确计算 | 用脚本 / 工具 / 固定步骤，不靠手写 |

生成式产物（图形、版式、表格、配置）适合重复生成时，可写成**参数化脚本**：把可调整参数集中定义，修改后重新生成并验收。需要保留时放外部档案的`outputs/drafts/`或现有项目约定位置，不写入工具源码目录。

## 4. 冲突处理（来源说法不一致时）

小冲突当场判断，必要时说明理由。重要来源冲突可用以下角度处理，不要求另开一个完整流程：

1. **盘点**：每个来源是什么类型、多新、多权威、覆盖什么。
2. **对照**：哪些话题多个来源都讲了；一致、互补还是分歧；术语统一。
3. **辨冲突**：真冲突还是表述不同？属于事实矛盾、版本差异、流派分歧、过时与现行、适用范围不同中的哪一类？
4. **合并**：一致的取讲得最好的版本；冲突的按权威、新近、情境贴合度取舍，**保留被放弃的说法和理由**。
5. **找缺口**：只有单一来源的点、没查到的点、缺例子的点。
6. **综合**：形成适用方案，需要组织交接时写进作战图，推论内容标明。
7. **自检**：有没有自相矛盾、有没有把推论写成事实、缺口是否写明。

流派分歧不必强行统一——辨明各自适用的情况，按本任务情境选择。只有实质缺少本人偏好或情境时才“问”，不因Agent暂时拿不准就把专业取舍交回用户。

## 5. 偏好与专家意见冲突

例：专家普遍建议加一个品牌色，而用户在本任务明确要求黑白灰。
先判断建议是可替代的专业惯例，还是任务必须满足的硬约束。前者可按用户要求取舍，必要时说明代价；后者不能因偏好直接判为达标。只有冲突会实质影响结果且缺少本人选择时才问；过期记录先看当前情境是否仍适用，不因日期自动造关卡。

## 6. 输出

- 全量档案的`2_作战图.md`保留当前需要的依据、阶段、决策和重要冲突；轻量任务在当前对话或现有材料中说明即可。
- 展开有依赖的执行前明确必要方案，低成本探查可先于规划。执行中前提变化时更新受影响部分，不为计划完整延误有效行动。
