# 整合：作战图与决策登记

## 模块接口

| 要素 | 约定 |
|---|---|
| 目标 | 形成可执行、可交接的任务方案 |
| 输入 | 简报、流程卡、专家卡、适用偏好及未决事项 |
| 职责 | Agent组织行业适配；本人决定专属取舍 |
| 处理 | 统一阶段接口，登记算/查/问/确认与依赖 |
| 输出 | 单张阶段交接表、决策与冲突记录 |
| 验收 | 输入输出衔接，检查项可判断，待答事项未伪装已定 |
| 交接 | 执行使用已定方案；答复或上游变化时更新受影响项 |

目录：作战图 → 决策登记 → 每步自由度 → 冲突处理 → 偏好与专家意见冲突 → 输出

## 1. 作战图（写进 2_作战图.md）

只维护一张实际任务的阶段表，把必要的专家分工与检查合在同一处：

| 阶段 | 目标 | 输入 | 职责 | 处理 | 输出 | 验收 | 交接 | 状态 |
|---|---|---|---|---|---|---|---|---|

- 职责写主导与把关；处理写必要的方法和自由度；验收写检查项与证据；交接写接收方、必要关卡G编号及未决事项。
- 一个人（或一个模型）可以兼任多个角色；写清此刻戴的是哪顶帽子。
- 检查项从专家卡的"考虑点"里挑与本阶段相关的，不全量照搬。
- 用户偏好和否决记录是硬约束，写在 `1_简报.md`，作战图引用即可。
- 流程里本任务用不到的阶段删掉，写一句删除理由。

## 2. 决策登记

把会影响结果的决定一条条列出来，每条标类型（算 / 查 / 问 / 确认，定义见 SKILL.md）和次序：

| # | 决定 | 类型 | 次序 | 依据 / 由谁定 | 状态 |
|---|---|---|---|---|---|
| D1 | 报告的主要读者 | 问 | 1 | 关卡G1（示例） | 已答 G1 |
| D2 | 图表的表达方式 | 问 | 3 | 先核对字段D3，再由G2选择（示例） | 已答 G2 |
| D3 | 输入字段是否完整 | 算 | 2 | 字段检查脚本（示例） | 已定 |

- **次序**：上游先于依赖它的下游；"问"之前把它依赖的"算""查"排在前面。
- 执行中冒出新决定，随时加行。
- `eca check`核对问/确认是否关联真实已答关卡；问类使用假设时必须有简报中的明确自主授权，确认不能靠假设放行。

分类拿不准时：行业有共识 → 查；没有共识、因人而异 → 问；能写成脚本判过 / 不过 → 算。

## 3. 每步自由度

| 自由度 | 适合 | 写法 |
|---|---|---|
| 高 | 多种做法都合理、靠判断 | 写目标和原则，让模型自己选路 |
| 中 | 有偏好的做法但允许变化 | 写步骤和参数范围 |
| 低 | 容易出错、要求一致、不可逆、可精确计算 | 用脚本 / 工具 / 固定步骤，不靠手写 |

生成式产物（图形、版式、表格、配置）适合重复生成时，可写成**参数化脚本**，从第一版起放 `outputs/drafts/`：把可调整参数集中定义，修改后重新生成并验收。

## 4. 冲突处理（来源说法不一致时）

小冲突当场判断，写一句理由即可。来源多、冲突多（深档）时按下面顺序处理，可在一次思考里完成：

1. **盘点**：每个来源是什么类型、多新、多权威、覆盖什么。
2. **对照**：哪些话题多个来源都讲了；一致、互补还是分歧；术语统一。
3. **辨冲突**：真冲突还是表述不同？属于事实矛盾、版本差异、流派分歧、过时与现行、适用范围不同中的哪一类？
4. **合并**：一致的取讲得最好的版本；冲突的按权威、新近、情境贴合度取舍，**保留被放弃的说法和理由**。
5. **找缺口**：只有单一来源的点、没查到的点、缺例子的点。
6. **综合**：写进作战图，推论内容标明。
7. **自检**：有没有自相矛盾、有没有把推论写成事实、缺口是否写明。

流派分歧不必强行统一——写出各自适用的情况，按本任务情境选一个；选不出来、且属于口味问题，就登记为"问"。

## 5. 偏好与专家意见冲突

例：专家普遍建议加一个品牌色，而用户说过只要黑白灰。
做法：按用户偏好执行；在冲突表记"专家建议 X，因用户偏好未采用"；影响大就登记为"问"，在下一个关卡提出。偏好记录可能过时，这本身就是开关卡的理由。

## 6. 输出

- `2_作战图.md`：用到的卡片、作战图、裁剪理由、决策登记、冲突与取舍。
- 作战图定下后再动手；执行中图错了或关卡改了方向，当场改这里并在日志记原因。
