# 固化：把稳定的流程和专家打包成独立技能

## 模块接口

| 要素 | 约定 |
|---|---|
| 目标 | 在重复需求得到验证时固化独立技能 |
| 输入 | 稳定卡片、重复使用证据及目标环境 |
| 职责 | Agent在已授权范围内实现与验证 |
| 处理 | 先复用，必要时提取最小入口与条件加载资源 |
| 输出 | 可发现的Skill及其实际需要的资源 |
| 验收 | 结构和代表性行为通过检查；不扩展任务权限 |
| 交接 | pack分发；需要客户端格式转换时用既有迁移工具 |

只在条件满足时做。默认不做。

## 1. 先判断要不要造

按顺序问：

1. **已有可用的吗？** 库里的卡片或现成技能已经够用 → 直接复用（必要时组合几张卡），不造。
2. **只是这一次需要？** → 用本工具包的流程直接做，不造。
3. **同类需求反复出现，且已有证据显示固化能带来复用收益？** → 才造独立技能。

需要为后续维护说明选择时，在现有项目材料保留理由，不为一次否定判断单独建档。没有重复证据就不造。

## 2. 造成什么样

- 文件夹名 = 技能名：小写字母、数字、连字符，64 字符以内，最好动词开头。
- `SKILL.md` 头部需要`name`和`description`，许可等受支持字段按需保留。description 写清做什么、什么时候用、什么时候不用，1024字符以内、不含尖括号，帮助宿主发现和选择技能。
- 正文写模型不知道的东西：流程阶段表、专家检查项、硬约束、关键数值，以及这类任务里哪些决定通常要"问"（从 `eca stats` 和复盘里来）。模型本来就会的不写。正文控制在 500 行内。
- 细节放 `references/`，一层深，每个文件在 SKILL.md 里写明何时读。
- 只有容易出错、需要一致、可精确计算的步骤才写成 `scripts/`，并且实际运行测试过。
- 不放 README、更新日志、安装说明等给人看的附属文件。

## 3. 检查与分发

- `python3 cli/eca.py check <技能目录>`：检查命名、description、引用文件是否存在。
- `python3 cli/eca.py pack`：将本工具包的方法ZIP和单文件版写入外部数据目录的`dist/`；也可用`--output-dir`选择外部分发目录。不包含私人任务资料，也不替代目标环境的安装。
- 要装进目标客户端的插件系统时，按该客户端当前官方格式转换；本工具包不绑定特定的格式迁移项目。
- 用过几次后回到复盘，按 retro.md 刷新或扩充。

## 来源与改写

技能结构、渐进披露和资源拆分参考并重新表述自[OpenAI skill-creator的固定版本](https://github.com/openai/skills/tree/49f948faa9258a0c61caceaf225e179651397431/skills/.system/skill-creator)（Apache-2.0），结合本工具的任务档案与卡片做了裁剪和重组。归属和许可随完整工具包及导出物保留。
